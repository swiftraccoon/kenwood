# kenwood-tmd750

Async Rust library for the Kenwood TM-D750: typed CAT control of both bands
including transmit, the TNC and the APRS beacon; MCP configuration backups and
verified page writes; menu fields decoded and planned per Programmable-Memory
slot; memory channels; Reflector Terminal startup and restoration; and `.d750`
configuration files. The menu registry is generated by
[`mcp-d75-extract`](https://github.com/swiftraccoon/kenwood/tree/main/mcp-d75-extract)
from the official MCP-D750 program's memory layout. Physical serial I/O, the
transport trait, transport errors and the scripted mocks come from
[`kenwood-transport`](https://github.com/swiftraccoon/kenwood/tree/main/kenwood-transport).
This crate owns TM-D750 endpoint discovery, the serial line settings, and every
radio protocol and recovery rule. It does not depend on the TH-D75 library.

## Start here

| Task | Entry point |
| --- | --- |
| Identify the radio and read its state | [`Radio::identify`], the `Radio::get_*` methods |
| Change a setting over CAT | the `Radio::set_*` methods |
| Transmit, beacon, select the TNC mode, VOX or power | [`Radio::transmit`], [`Radio::send_aprs_beacon`], [`Radio::set_tnc_mode`], [`Radio::set_vox`], [`Radio::power_off`] |
| Store, recall and clear memory channels | [`Radio::write_memory_channel`], [`Radio::recall_memory_channel`], [`Radio::clear_memory_channel`] |
| Back up the configuration | [`Radio::backup_mcp_until_exit`] |
| Decode a capture offline | [`MenuFieldSnapshot`], [`ChannelAccess`], [`memory::TextImage`], [`memory::ReflectorTerminalPreflight`] |
| Compare two captures | [`memory::StandardConfigurationDiff`] |
| Change menu settings | [`MenuUpdatePlan`] and [`radio::McpSession::compare_exchange_menu_update`] |
| Change a text field (PM1 name, MY1, a channel name) | [`memory::TextFieldUpdate`] and [`Radio::set_text_field_session_until_exit`] |
| Write arbitrary pages | [`PageReplacement`] and [`radio::McpSession::compare_exchange_pages`] |
| Run Reflector Terminal | [`TerminalLifecycle`] and [`TerminalRecovery`] |
| Read or write a `.d750` file | [`parse_d750`], [`RadioConfig`] |

The crate is used from the workspace or as a local path dependency:

```toml
[dependencies]
kenwood-tmd750 = { path = "../kenwood/tmd750" }
kenwood-transport = { path = "../kenwood/kenwood-transport", default-features = false }
tokio = { version = "1", features = ["rt", "macros", "time"] }
```

The model enables the shared serial backend. The companion
[`tmd750-repl`](https://github.com/swiftraccoon/kenwood/tree/main/tmd750-repl)
wires native Bluetooth, capture transcripts and journals to this library.

## Connect and read status

[`transport::discover_serial`] lists ports, TM-D750 endpoints first, without
opening any; USB metadata selects candidates and only an `ID` reply proves the
model. Open the chosen endpoint inside a Tokio runtime, identify the radio,
and close the transport whatever the outcome:

```rust,no_run
use kenwood_tmd750::{Band, Error, Radio};
use kenwood_tmd750::transport::{DEFAULT_BAUD, open_serial};
use kenwood_transport::{Transport, TransportError};

#[derive(Debug, thiserror::Error)]
#[error("status failed: operation={operation:?}; close={close:?}")]
struct StatusFailure {
    operation: Option<Error>,
    close: Option<TransportError>,
}

#[tokio::main(flavor = "current_thread")]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Replace with the selected path or Windows COM port.
    let transport = open_serial("/dev/cu.usbmodem101", DEFAULT_BAUD)?;
    let mut radio = Radio::new(transport);
    let operation = async {
        let identity = radio.identify().await?;
        let mode = radio.get_operating_mode(Band::A).await?;
        let gateway = radio.get_dv_gateway_mode().await?;
        Ok::<_, Error>((identity, mode, gateway))
    }
    .await;
    let mut transport = radio.into_transport();
    let close = transport.close().await;
    drop(transport);
    match (operation, close) {
        (Ok((identity, mode, gateway)), Ok(())) => {
            println!("{identity}; Band A {mode}; DV Gateway {gateway}");
            Ok(())
        }
        (operation, close) => Err(StatusFailure {
            operation: operation.err(),
            close: close.err(),
        }
        .into()),
    }
}
```

Over Bluetooth, [`transport::bluetooth::select_paired_device`] picks the one
paired device listed under a TM-D750 name ([`transport::bluetooth::BLUETOOTH_NAMES`])
from the records `kenwood-transport` returns with its `native-bluetooth`
feature; open the selected address with that crate and construct the radio
with [`Radio::new_bluetooth`].

`cargo run -p kenwood-tmd750 --example status -- PORT` prints every typed read
of both bands and of the global settings; `--example identify` prints the
identity, power state, serial information, clock and DV Gateway state;
`--example d750_channels -- FILE` lists the programmed channels of a `.d750`
file; `--example owned_lifecycle` runs the complete ownership lifecycle on
strict mocks.

## Safety model

- **Write targets.** Every setter, transmit command, MCP write and plan checks
  the radio against [`WRITE_TARGETS`] (`TM-D750 / 1.02 / K,2,1`) before
  sending a byte and returns [`Error::UnsupportedWriteTarget`] otherwise.
  Reads work on any TM-D750.
- **Echo and readback.** A CAT setter requires the echo to equal the request,
  then reads the setting back: [`ProtocolError::EchoMismatch`] and
  [`ProtocolError::ReadbackMismatch`] report the differing values. `FQ` outside
  a band's receive ranges tunes a nearby frequency instead of refusing, which
  [`Error::FrequencyAdjusted`] reports with the tuned frequency. Nothing is
  rolled back.
- **One command, one reply.** Each command reads lines until one answers it
  (`?` is [`ProtocolError::Rejected`], `N` is [`ProtocolError::NotAvailable`]),
  discarding up to [`radio::MAX_STALE_LINES`] others, and after a `?` the next
  two commands discard the repeated reply firmware 1.02 sends.
- **Uncertain connections.** A timeout, transport failure, dropped future or
  undecodable reply leaves the connection uncertain: further commands return
  [`McpError::RecoveryRequired`] before any I/O. After a CAT failure (not an
  MCP one) [`Radio::receive`] still sends `RX`, so a keyed transmitter can be
  released, and its reply makes the connection ready again.
- **Programming sessions.** [`Radio::enter_mcp`] borrows the radio as a
  [`radio::McpSession`]. [`radio::McpSession::exit`] sends one `E` and waits for
  its ACK, then retires the handle ([`McpError::ConnectionRetired`]): close and
  drop it, and identify a fresh connection. Every page write compares the
  complete before-image freshly first, calls a journal callback that must
  record and synchronize the intent, writes once and reads the page back.
- **Cancellation.** Await every operation to completion; asynchronous cleanup
  cannot run from a destructor. Long operations take a cancellation callback
  checked between complete exchanges.

## Control the radio over CAT

Every value is a validated type, every read is one query, and every write runs
the write-target gate, the echo check and the readback:

```rust,no_run
use kenwood_tmd750::types::{Frequency, PowerLevel, SquelchLevel, StepSize, TuningMode};
use kenwood_tmd750::{Band, Error, Radio};
use kenwood_transport::Transport;

async fn tune<T: Transport>(radio: &mut Radio<T>) -> Result<(), Error> {
    radio.set_tuning_mode(Band::A, TuningMode::Vfo).await?;
    radio.set_step_size(Band::A, StepSize::Hz5000).await?;
    radio.set_frequency(Band::A, Frequency::from_mhz_str("146.520")?).await?;
    radio.set_power_level(Band::A, PowerLevel::Low).await?;
    radio.set_squelch(Band::A, SquelchLevel::new(8)?).await?;
    println!("{}", radio.get_channel_record(Band::A).await?);
    println!("{}", radio.frequency_up(Band::A).await?);
    Ok(())
}
```

The typed surface covers the operating mode (FM, DV, AM, NFM; DR is the
tuning mode [`types::TuningMode::DStarRepeater`]), frequency, the VFO channel
record, power, tuning mode, squelch, S-meter, busy, attenuator, tuning step, AM
high cut, memory selection and recall, the six D-STAR MY callsign slots and
their selection, band roles, band display, panel lighting, the APRS position
source, packet rate, beacon method and My Callsign, VOX delay, gain and state,
GPS settings and NMEA sentences, Bluetooth, the TNC mode, power, the clock, the
serial number and the DV Gateway state. `frequency_up` and `frequency_down`
step the control band and read the frequency back until the step lands,
because the radio acknowledges `UP` and `DW` before applying them.
[`Radio::set_channel_record`] replaces a band's whole VFO record (`FO`) in one
write, and its errors carry both records' wire fields.

The D-STAR MY slots of `DC` are the six-entry list of ordinary DV operation;
[`memory::MyCallsignList`] decodes it and its `DS` selection from a backup.
The DV Gateway MY list that Terminal and Direct modes transmit is a separate,
MCP-only list ([`memory::My1CallsignUpdate`]).

### Memory channels

`ME` reads, stores and clears channels, and `MR` recalls one on a band in
Memory tuning mode:

```rust,no_run
use kenwood_tmd750::types::{Band, MemoryChannelAddress, TuningMode};
use kenwood_tmd750::{Error, Radio};
use kenwood_transport::Transport;

async fn copy_channel<T: Transport>(radio: &mut Radio<T>) -> Result<(), Error> {
    let source = MemoryChannelAddress::regular(21)?;
    let target = MemoryChannelAddress::regular(22)?;
    if let Some(record) = radio.get_memory_channel(source).await? {
        let stored = radio.write_memory_channel(target, record).await?;
        println!("stored {}", stored.channel);
        radio.set_tuning_mode(Band::A, TuningMode::Memory).await?;
        radio.recall_memory_channel(Band::A, target).await?;
        radio.clear_memory_channel(target).await?;
    }
    Ok(())
}
```

A stored channel reads back as written except that an empty URCALL becomes
`CQCQCQ`; the priority channel refuses writes. Channel names are not part of
the CAT record: a store keeps a channel's name, a clear erases it, and only
an MCP write sets one. [`memory::ChannelNameUpdate`] writes one name with its
own two-session check, and [`ChannelAccess`] decodes records, flags and names
from a backup.

To program many channels, [`Radio::program_memory_channels`] stores and
clears them over CAT in order, reporting the channels finished when one
fails, and [`radio::McpSession::write_channel_names`] then writes a
[`memory::ChannelNamePlan`] in one programming session: it reads the touched
name-table pages fresh and compare-exchanges the ones that change.

```rust,no_run
use kenwood_tmd750::Radio;
use kenwood_tmd750::memory::{ChannelNamePlan, ChannelNameText};
use kenwood_tmd750::radio::ChannelWrite;
use kenwood_tmd750::types::{CatMemoryChannelRecord, MemoryChannelAddress, PhysicalChannel};
use kenwood_transport::Transport;

async fn program<T: Transport>(
    radio: &mut Radio<T>,
    record: CatMemoryChannelRecord,
) -> Result<(), Box<dyn std::error::Error>> {
    let address = MemoryChannelAddress::regular(40)?;
    radio
        .program_memory_channels(&[(address, ChannelWrite::Store(record))], |_| {})
        .await?;
    let plan = ChannelNamePlan::new([(
        PhysicalChannel::from_address(address),
        Some(ChannelNameText::new("Simplex 40")?),
    )])?;
    let mut session = radio.enter_mcp().await?;
    session.write_channel_names(&plan, |_| Ok(()), |_| {}).await?;
    session.exit().await?;
    Ok(())
}
```

After the exit, close the transport and verify a fresh identity before any
further CAT, as for every programming session.

### Transmit

[`Radio::transmit`] keys the PTT band (the second [`types::BandControl`] field)
on its current frequency, mode and power level; the radio answers `TX 1` and
transmits until [`Radio::receive`], its time-out timer or power loss.
[`Radio::transmit_for`] keys, waits and releases:

```rust,no_run
use std::time::Duration;
use kenwood_tmd750::types::{Frequency, PowerLevel};
use kenwood_tmd750::{Band, Error, Radio};
use kenwood_transport::Transport;

async fn short_test_carrier<T: Transport>(radio: &mut Radio<T>) -> Result<(), Error> {
    let ptt = radio.get_band_control().await?.ptt;
    radio.set_power_level(ptt, PowerLevel::Low).await?;
    radio.set_frequency(ptt, Frequency::from_mhz_str("223.440")?).await?;
    radio.transmit_for(Duration::from_millis(250)).await
}
```

[`Radio::transmit_until`] releases when a caller's future completes, such as a
deadline raced against an interrupt, and never polls that future when `TX` is
refused. When the `TX` exchange fails after the command may have reached the
radio, it sends `RX` before returning that failure, so
[`Error::ReleaseUnconfirmed`] is the one error after which the transmitter may
still be keyed. Dropping a transmit future does not release the transmitter.
The caller is responsible for the license conditions of every transmission.

### TNC, APRS beacon, VOX and power

[`Radio::set_tnc_mode`] selects off, APRS or KISS on a data band (`TN 2,0`
enters KISS mode on Band A, `TN 2,1` on Band B, per the User Manual). In APRS
mode the `Auto` and `SmartBeaconing` beacon methods transmit by themselves;
with `Manual` selected, [`Radio::send_aprs_beacon`] transmits one beacon
carrying the APRS My Callsign and the selected position, and `BE` is answered
`N` while the TNC is off. Over the operation-panel USB endpoint a KISS
selection re-enumerated that endpoint before replying, and the TNC read off
on the next connection. [`Radio::set_vox`] lets microphone audio key the
transmitter and waits [`radio::VOX_SETTLE`] before returning, because a `VX`
write sent at once is refused. [`Radio::power_off`] sends `PS 0`; its reply has
not been read from a radio.

### GPS sentences

With GPS PC output on ([`Radio::set_gps_settings`], Menu 403) the radio sends
the sentences [`types::NmeaSentences`] selects to the interface Menu 982
names. [`nmea::LineReader`] picks those sentences out of a byte stream that
may interleave CAT replies, and [`nmea::Sentence::parse`] checks one line's
checksum and decodes GGA and RMC into time, position, fix, speed, course and
date, keeping every other sentence with its fields. The decoding follows the
NMEA 0183 formats; no capture of the radio's own output has been decoded yet.

```rust
use kenwood_tmd750::nmea::{LineReader, Sentence};

let mut reader = LineReader::new();
for sentence in reader.push(b"ID TM-D750\r$GPGGA,123519,4807.038,N,01131.000,E,1,08,0.9,545.4,M,46.9,M,,*47\r\n") {
    if let Ok(Sentence::Gga(fix)) = sentence {
        println!("{:?} with {:?} satellites", fix.position, fix.satellites);
    }
}
```

## Programming mode (MCP)

Programming-mode entry interrupts normal operation. The address regions are
the ones the official program transfers: the global settings and four menu
blocks for each of the six Programmable-Memory slots, in 256-byte pages under
five-byte headers whose echo is verified.

### Probe and back up

[`Radio::probe_mcp`] reads two fixed fragments (`8..48` and `327681..327936`)
and exits. [`Radio::backup_mcp_until_exit`] reads the standard configuration:
1,138 pages, 289,962 bytes, every PM slot, without the custom startup bitmap.
The report keeps every acknowledged page on failure or cancellation, and
[`McpBackupReport::has_complete_configuration`] checks the whole ordered
schedule. [`Radio::backup_mcp_gateway_off_until_exit`] first requires a write
target and a fresh `GW 0` ([`Error::GatewayNotOff`] otherwise).

```rust,no_run
use kenwood_tmd750::{Error, McpProbeOutcome, Radio};
use kenwood_transport::Transport;

async fn probe<T: Transport>(radio: &mut Radio<T>) -> Result<(), Error> {
    let report = radio.probe_mcp(|| false).await;
    for segment in &report.segments {
        println!("read {} bytes at {}", segment.data.len(), segment.page.address().as_u32());
    }
    match report.outcome {
        McpProbeOutcome::AwaitingCatVerification => {
            println!("exit acknowledged; close this handle and identify a fresh connection");
        }
        McpProbeOutcome::Cancelled => println!("stopped at an exchange boundary"),
        McpProbeOutcome::Failed { stage, error } => {
            eprintln!("failed at {stage:?}; exit disposition: {:?}", report.exit);
            return Err(error);
        }
    }
    Ok(())
}
```

### Inspect captures offline

[`MenuFieldSnapshot`] holds complete captured pages and decodes any registered
field whose pages it covers; [`ScopedMenuField`] requires a slot for per-PM
fields and rejects one for global fields. [`memory::TextImage`] decodes and
previews the supported text settings, [`ChannelAccess`] the memory channels,
and [`memory::ReflectorTerminalPreflight`] the Terminal settings of one slot.
Decoding describes the supplied bytes; the caller establishes their
provenance and coverage.

[`memory::repeater_list::RepeaterList`] reads the D-STAR repeater list (1,500
slots) or the hotspot list (30) in the radio's chain order, and
[`memory::repeater_list::RepeaterNames`] the world-region, country and group
names its records index. [`memory::repeater_list::RepeaterRecord::page_replacement`]
turns an edited record into the one page write that stores it in place;
[`memory::repeater_list::RepeaterList::from_records`] and
[`memory::repeater_list::RepeaterList::page_replacements`] store a whole list
in a new order, and [`memory::repeater_list::RepeaterNames::page_replacements`]
renamed tables. Each produces page writes for
[`radio::McpSession::compare_exchange_pages`].

```rust
use kenwood_tmd750::MemoryImage;
use kenwood_tmd750::memory::repeater_list::{
    RepeaterList, RepeaterListError, RepeaterListKind, RepeaterNames,
};

fn print_repeaters(image: &MemoryImage) -> Result<(), RepeaterListError> {
    let names = RepeaterNames::read(image)?;
    for (slot, record) in RepeaterList::read(image, RepeaterListKind::Repeater)?.iter() {
        let group = record.group().map(|group| names.group(group).to_string());
        println!(
            "{slot}: {} {} {} {}",
            record.name(),
            record.callsign(),
            record.frequency(),
            group.unwrap_or_default()
        );
    }
    Ok(())
}
```

[`memory::callsign_list::CallsignList`] reads the D-STAR callsign list, up to
300 named destination callsigns with memos, in display order;
[`memory::callsign_list::CallsignList::from_entries`] and
[`memory::callsign_list::CallsignList::page_replacements`] store an edited
list compact from its first slot. The list's ends share a page with the
repeater list's, and a write of either list compares that page whole. Names,
sub-names and memos of both lists are [`memory::StoredText`].

```rust
use kenwood_tmd750::memory::StoredText;
use kenwood_tmd750::memory::callsign_list::{CallsignEntry, CallsignList};
use kenwood_tmd750::types::StoredCallsign;
use kenwood_tmd750::{MemoryImage, PageReplacement};

fn add_reflector_link(image: &MemoryImage) -> Result<Vec<PageReplacement>, Box<dyn std::error::Error>> {
    let mut entries: Vec<CallsignEntry> =
        CallsignList::read(image)?.iter().map(|(_, entry)| entry.clone()).collect();
    entries.push(CallsignEntry::new(
        StoredText::new("REF001 C")?,
        StoredCallsign::new("REF001CL")?,
        StoredText::new("Link reflector 1 C")?,
    )?);
    Ok(CallsignList::from_entries(entries)?.page_replacements(image)?)
}
```

```rust
use kenwood_tmd750::MemoryImage;
use kenwood_tmd750::memory::{TextError, TextImage, TextPreview, TextScope, TextSetting};

fn preview_pm_name(image: &MemoryImage) -> Result<TextPreview, TextError> {
    TextImage::new(image).preview(TextSetting::PmName1, TextScope::Global, "Local repeaters")
}
```

```rust
use std::ops::Range;
use kenwood_tmd750::{MemoryImage, SlotIndex};
use kenwood_tmd750::memory::{ReflectorTerminalPreflight, TerminalUsbRoute};

fn inspect_terminal(
    image: &MemoryImage,
    captured_ranges: &[Range<u32>],
    slot: SlotIndex,
) -> Result<ReflectorTerminalPreflight, Box<dyn std::error::Error>> {
    for field in ReflectorTerminalPreflight::required_fields()? {
        let start = field.address(Some(slot))?.as_u32();
        let end = start
            .checked_add(u32::try_from(field.codec.encoded_len())?)
            .ok_or("field range overflow")?;
        if !(start..end).all(|address| captured_ranges.iter().any(|range| range.contains(&address))) {
            return Err("capture lacks a required Terminal field".into());
        }
    }
    Ok(ReflectorTerminalPreflight::read(image, slot, TerminalUsbRoute::MainUnit)?)
}
```

### Compare captures

[`memory::StandardConfiguration`] validates the exact standard transfer
schedule, and [`memory::StandardConfigurationDiff`] compares two of them with
equal identities byte for byte:

```rust
use kenwood_tmd750::{Identity, Page};
use kenwood_tmd750::memory::{ConfigurationError, StandardConfiguration, StandardConfigurationDiff};

fn compare_captures(
    before_identity: &Identity,
    before_pages: &[(Page, Vec<u8>)],
    after_identity: &Identity,
    after_pages: &[(Page, Vec<u8>)],
) -> Result<StandardConfigurationDiff, ConfigurationError> {
    let before = StandardConfiguration::new(
        before_identity,
        before_pages.iter().map(|(page, data)| (*page, data.as_slice())),
    )?;
    let after = StandardConfiguration::new(
        after_identity,
        after_pages.iter().map(|(page, data)| (*page, data.as_slice())),
    )?;
    StandardConfigurationDiff::between(&before, &after)
}
```

A write whose outcome is uncertain after an acknowledged exit is resolved by a
fresh backup compared with the pre-write backup, never by repeating the
session.

[`memory::Configuration`] keeps a capture whole: the identity it was read
from, the pages read and their bytes. It returns no unread byte, offers the
standard and menu views and the same comparison, and has a persisted form
with a CRC-32 that [`memory::Configuration::to_bytes`] writes and
[`memory::Configuration::from_bytes`] reads back exactly:

```rust
use kenwood_tmd750::McpBackupReport;
use kenwood_tmd750::memory::{Configuration, ConfigurationError};

fn keep(report: &McpBackupReport) -> Result<Vec<u8>, ConfigurationError> {
    let captured = Configuration::from_backup(report)?;
    let stored = captured.to_bytes();
    assert_eq!(Configuration::from_bytes(&stored)?, captured);
    Ok(stored)
}
```

### Change menu settings

[`MenuUpdatePlan`] binds registered-field assignments to captured pages and
operating guards: a write-target identity, memory format zero, a valid active
PM, Gateway Off in that PM, and complete source pages for every assignment and
guard. [`radio::McpSession::compare_exchange_menu_update`] compares the plan's
identity with the session's and every page freshly before the first write:

```rust
use kenwood_tmd750::memory::MenuFieldId;
use kenwood_tmd750::{Identity, MenuAssignment, MenuFieldSnapshot, MenuUpdateError, MenuUpdatePlan, SlotIndex};

fn prepare_settings(
    identity: &Identity,
    snapshot: &MenuFieldSnapshot,
    slot: SlotIndex,
) -> Result<MenuUpdatePlan, MenuUpdateError> {
    MenuUpdatePlan::new(identity, snapshot, vec![
        MenuAssignment::new("pm.PmName2", None, "BASE")?,
        MenuAssignment::for_field(MenuFieldId::RADIO_TX_EQUALIZER_FM_NFM, Some(slot), "on")?,
    ])
}
```

[`memory::MenuFieldId`] names every registered field with an associated
constant (`RADIO_TX_EQUALIZER_FM_NFM` for `radio.TxEqualizerFmNfm`), generated
with the registry, so [`MenuAssignment::for_field`] needs no string key.
[`memory::MenuField::write_policy`] separates ordinary fields from unresolved
domains, binary data and fields with another lifecycle; only ordinary fields
enter a plan. Numeric input denotes stored values, not display units.

### Change a text field

[`memory::TextFieldUpdate`] prepares one text field inside one complete
256-byte page and sequences an apply session and a separate verification
session; [`Radio::set_text_field_session_until_exit`] runs each session:

| Alias | Field | Value | Guards |
|-------|-------|-------|--------|
| [`memory::Pm1NameUpdate`] | the global PM1 name | [`memory::Pm1Name`]: 1 to 16 printable ASCII bytes | none |
| [`memory::My1CallsignUpdate`] | DV Gateway MY1 of PM Off | [`memory::My1Callsign`]: 1 to 8 uppercase letters, digits or spaces | PM Off and MY1 selected, Gateway Off stored and observed before entry and after exit, PM control page unchanged |
| [`memory::ChannelNameUpdate`] | one physical channel's name | [`memory::ChannelNameText`]: 1 to 16 printable ASCII bytes, or none | none |

```rust
use kenwood_tmd750::memory::{ChannelNameText, ChannelNameUpdate, TextFieldUpdateError};
use kenwood_tmd750::{Identity, PhysicalChannel};

fn prepare_channel_name(
    identity: &Identity,
    captured_page: &[u8],
    channel: PhysicalChannel,
    desired: &str,
) -> Result<ChannelNameUpdate, TextFieldUpdateError> {
    ChannelNameUpdate::prepare(identity, captured_page, channel, None, Some(&ChannelNameText::new(desired)?))
}
```

Only the field's bytes may change; every other byte of the page is compared
in both sessions. The caller's `before_write` callback records and
synchronizes both complete pages before the one write. An unchanged request is
[`memory::TextFieldUpdateError::NoChange`].

### Raw page writes

[`PageReplacement`] pairs the complete expected and replacement bytes of one
canonical writable page, and [`radio::McpSession::compare_exchange_pages`]
writes a batch of them under the write-target gate with the same fresh
comparison, journal callback and readback, but without the PM, Gateway and
format guards of the plans. [`MenuFieldSnapshot::plan_exchanges`] builds
replacements from a [`PatchPlanner`] patch set.

### One-call sessions

[`radio::session::write_pages`] runs a page plan in the order the hardware
requires, through a [`radio::readiness::ControlHost`] such as
[`radio::readiness::SystemControlHost`]: the settle wait on an
operation-panel endpoint, one open, the identity the plan was prepared from,
Gateway Off, the compare-exchange with a [`radio::session::WriteJournal`]
called before each write, the exit, the close, and a fresh identity with
Gateway Off. [`radio::session::backup`] runs the same order around a standard
backup. The returned report records every step reached; nothing is retried or
rolled back.

```rust,no_run
use std::sync::atomic::AtomicBool;

use kenwood_tmd750::radio::readiness::SystemControlHost;
use kenwood_tmd750::radio::session;
use kenwood_tmd750::transport::{DEFAULT_BAUD, SerialCandidate};
use kenwood_tmd750::{Identity, PageReplacement};

async fn write(
    endpoint: &SerialCandidate,
    identity: &Identity,
    plan: &[PageReplacement],
) -> Result<(), Box<dyn std::error::Error>> {
    let mut host = SystemControlHost::new();
    let mut journal = |page: &PageReplacement| {
        println!("writing {}", page.page().address().as_u32());
        Ok(())
    };
    let report = session::write_pages(
        &mut host,
        endpoint,
        DEFAULT_BAUD,
        identity,
        plan,
        &mut journal,
        &AtomicBool::new(false),
    )
    .await;
    if report.succeeded() {
        Ok(())
    } else {
        Err(format!("session stopped: {:?}", report.error).into())
    }
}
```

### Reflector Terminal

[`TerminalPlan`] changes only the Gateway mode, its subtype and, when
requested, the route, and its restoration swaps the exact images back.
[`TerminalLifecycle`] owns entry, the MMDVM handoff and restoration over three
caller-implemented traits: [`ControlHost`] (the independent serial control
endpoint), [`ModemHost`] (the modem link) and [`TerminalJournal`]
(synchronized records of the backup, plan, intents and checkpoints). With
Gateway Off the Terminal pages are written over the modem link; with a
Terminal route active they are written over the control endpoint, and the
modem link is never sent CAT. [`TerminalRecovery::finish`] rewrites exactly
the pages startup changed, and only after the modem connection is confirmed
closed.

## Configuration files

[`parse_d750`] validates the header signature, the `TM-D750` model marker, the
zero reserved byte at offset 32 and the signature-selected payload length:
`MCP-D750` requires the full 1,929,472-byte image and `TM-D750` the
393,216-byte prefix. [`RadioConfig`] keeps exactly the stored bytes, and an
unmodified file round-trips byte for byte:

```rust
use kenwood_tmd750::{FileError, RadioConfig, RadioType, parse_d750};
use kenwood_tmd750::file::ConfigHeader;

fn round_trip(data: &[u8]) -> Result<Vec<u8>, FileError> {
    let config = parse_d750(data)?;
    assert_eq!(
        config.image_bytes().len(), config.layout().image_bytes(),
        "stored payload coverage must match the validated header",
    );
    Ok(config.to_bytes())
}

fn full_file(radio_type: &RadioType, image: Vec<u8>) -> Result<RadioConfig, FileError> {
    let header = ConfigHeader::for_mcp_d750(radio_type)?;
    RadioConfig::new(header, image)
}
```

## Timing

These are host bounds sized from observation on firmware 1.02, not firmware
guarantees:

- After an MCP exit ACK the full identity answers 10 to 13 seconds later. The
  operation-panel endpoint can reappear within seconds, leave `ID` unanswered
  until the identity is ready, and re-enumerate once more after `ID` first
  answers, so a programming entry sent then fails with `ENXIO`.
  [`radio::readiness::verify_readiness`] polls a fresh identity within its
  budget, and [`radio::readiness::await_settled`] waits for ten seconds of
  continuous enumeration before a session opens on that endpoint.
- Native Bluetooth holds the first reply of a connection opened within about
  five seconds of the previous close, and of one opened after an MCP exit
  until about 20 seconds after the exit ACK. [`Radio::new_bluetooth`] and
  [`Radio::new_bluetooth_after_exit`] give that first reply its deadline.
- The radio acknowledges `UP` and `DW` within milliseconds, drops a second
  step within about 15 ms and refuses a setting write within about 20 ms of
  the acknowledgement; the step methods keep [`radio::STEP_SPACING`] and
  [`radio::STEP_SETTLE`].

## Hardware coverage

Tested on a TM-D750 reporting `ID TM-D750`, `FV 1.02`, `TY K,2,1`:

| Area | Interfaces |
| --- | --- |
| Every typed CAT read | main-unit USB, operation-panel USB, native Bluetooth |
| Every CAT setter, across each bounded domain | operation-panel USB; mode and squelch over native Bluetooth |
| `FO` VFO record replacement and restoration | operation-panel USB |
| `TX`/`RX` on either PTT band, APRS mode and one `BE` beacon, VOX on and off, with an unchanged standard backup afterwards | operation-panel USB |
| MCP probe and standard backup | main-unit USB, operation-panel USB, native Bluetooth |
| [`radio::session::backup`]: settle wait, backup, exit, close and fresh identity, matching the previous backup | operation-panel USB |
| Menu plans: one field of every admitted storage kind, per-slot writes in slots 1 to 5, a two-page plan | operation-panel USB; a byte field over native Bluetooth |
| Text field updates: PM1 name, PM Off MY1, a channel name | operation-panel USB, native Bluetooth |
| Reflector Terminal entry and restoration in PM Off | Bluetooth modem link with an operation-panel USB control endpoint |
| Repeater list and name tables of a standard backup holding 1,455 repeaters, checked against Kenwood's catalog; an in-place repeater frequency edit, reported by `FO` in DR mode and restored | operation-panel USB |
| Batch channel programming: two channels stored over CAT and named in one programming session, then cleared, with an unchanged standard backup afterwards | operation-panel USB |
| D-STAR callsign list: one entry added, read back in place in a fresh session, and removed, with an unchanged standard backup afterwards | operation-panel USB |

KISS mode over CAT and `PS 0` are not established, a `.d750` export has not
been opened by the official program, and the meaning of the three `TY`
components is unknown.

`tests/hardware.rs` repeats the read-only part against a connected radio: it
waits for an operation-panel endpoint to settle, reads every CAT getter on
both bands, runs the MCP probe and waits for the identity to return. It writes
no setting and transmits nothing:

```text
TMD750_PORT=/dev/cu.usbmodem0x001 cargo test -p kenwood-tmd750 --test hardware -- --ignored --nocapture
```

The `fuzz/` workspace holds libFuzzer targets for the CAT line parser, the MCP
header, the `.d750` parser, the stored channel codecs, the repeater-list
